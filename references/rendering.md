# 制作与验收细节

在需要实际制作、修改或导出像素动画时阅读。以下是参考片验证过的实现方式；其中时间、帧率、尺寸和音色均可按任务调整。

## 像素渲染

参考片在 480 × 270 的 Canvas 绘制，再关闭 `imageSmoothingEnabled`，放大四倍到 1920 × 1080。画幅为 16:9。输出 30 fps，动画动作按 `Math.floor(t * 15) / 15` 更新，形成轻微逐格感。竖屏影片应重新安排逻辑画布和构图，避免直接裁掉人物。

使用像素网格、整数位置和阶梯轮廓；镜头裁切的源坐标及宽高也取整。镜头推近后仍用最近邻放大，检查像素是否被插值模糊。字幕在最终输出层绘制，以保证中文可读性。

参考颜色：

| 用途 | 色值 |
| --- | --- |
| 主角陶土红 | `#d97757` |
| 天空青绿 | `#91c8cb`、`#bcdedd` |
| 草地与深绿 | `#8ca477`、`#617d68` |
| 玫瑰与花瓣 | `#de8094`、`#f4b3ab` |
| 金色点缀 | `#e9b85d` |
| 雨夜天空 | `#394565`、`#566984`、`#8a9ba7` |
| 星空 | `#2c3555`、`#424768`、`#697386` |
| 室内墙面与木地板 | `#dbd5c8`、`#baa596` |

参考片用六像素高的色带渐变表现天空，搭配像素云和明确的场景物体。让红色主角、粉色花朵、绿植与背景形成清楚的色彩关系。

## 动作与镜头

- 呼吸或静立起伏约 1 个逻辑像素；走路以每秒约 6 次的离散踏步表达。
- 花茎摆动约 1 至 2 个逻辑像素；云与花瓣速度明显慢于走路。粒子使用固定随机种子，同一时间戳始终渲染同一画面。
- 用局部进度 `p = (t - t0) / (t1 - t0)` 控制关键动作，再使用 smoothstep 缓入缓出。角色运动和物品运动要共享动作进度。
- 镜头缩放常为 1.18 至 1.85 倍，近景可到 2 倍；每镜只增加少量缩放。构图中心随主体选择，放大后重新检查头、手、道具和字幕位置。
- 参考片开头约 0.7 秒淡入，镜头间约 0.35 秒叠化，结尾约 0.5 秒淡出。根据节奏调整；叠化应独立绘制前后镜头，防止 Canvas 状态污染。

## 一个时间轴驱动所有产物

维护结构化镜头数据，至少包含 `shot`、`title`、`t0`、`t1`、`d`、字幕 `s` 和旁白 `voice`。`d = t1 - t0`，镜头连续覆盖总时长；场景索引与数据一一对应。

预览、逐帧导出、旁白排布及 SRT 都读取这份数据。旁白文本单独处理换行与外文发音，字幕保留角色名称和标点。镜头不是固定时长，长对白和转折应获得更多时间。

参考片字幕在镜头开始约 0.28 秒出现、结束前约 0.14 秒消失。1080p 输出中中文约 42 px、行高 54 px；用实际字体测量行宽，长句手动分行或减小字体，不允许越出画布。

若用户要求字幕开关，预览只改变字幕层，并在当前时间重新绘制，保持音频与播放状态。MP4 要支持关闭字幕时，应导出无烧录字幕的视频并封装 `mov_text` 字幕轨，另交付 SRT。说明依赖播放器支持，不能把烧录字幕说成可切换字幕。

## 声音

参考片使用 `edge-tts`：旁白 `zh-CN-XiaoxiaoNeural`，对话 `zh-CN-YunxiNeural`，语速 `-3%`。在当前环境检查可用音色；服务不可用时，可用 Windows 已安装中文语音并说明音质变化。联网调用最多重试三次，使用已配置代理，不把本机端口写成通用要求。

每句音频去除过长头尾静音，记录自然长度和所属镜头可用时长。参考片留约 0.65 秒余量、旁白从镜头开始后约 0.34 秒进入。略超时可用 FFmpeg `atempo` 调整；明显过快时压缩文案或延长镜头，不能直接截掉句尾。

语音缓存要与文本、音色及语速绑定。复用旧项目时，按镜头序号保存的音频可能已经过期，剧情变化后须更新对应缓存；恢复旧剧情则可复用确实匹配的旧旁白。

用 48 kHz 浮点轨道混音。参考片人声峰值约 0.65，音乐比人声明显低，使用简洁音符、衰减包络和轻微回声形成音乐盒质感。雨声用滤波噪声合成，按实际雨景时间淡入淡出。最终检查峰值不削波并试听，不能仅凭数字认定响度合适。

## 输出与验证

一套可用的文件分工为 `story.js` 时间轴、`sprite.js` 角色、`pixel-film.js` 场景、`anim.html` 预览、`audio.py` 声音、`export.js` 导出和 `verify.js` 验收。已有工程优先延续原分工。

Puppeteer 或 Playwright 打开预览，等待字体与渲染接口就绪。导出接口接受绝对时间或帧号，逐帧渲染而非实时录屏，避免丢帧和音乐时间漂移。

先写时间轴与 SRT、输出代表帧，再生成 `soundtrack.wav`，最后逐帧送入 FFmpeg。参考编码为 H.264、`yuv420p`、CRF 18、AAC 192k、`+faststart`。帧数取总时长乘帧率，不能更换时长后仍保留示例片的 3600 帧或 120 秒限制。

桌面预览允许暂停、续播、时间轴、帧号、章节跳转、静音与 SRT 下载。直接打开 HTML 能正常工作时无需服务器；浏览器禁止所需文件访问时使用本地服务。

验收包含：

1. 同一时间戳像素一致；相邻时间戳有预期运动；每镜非空白。不能仅以背景粒子变化判定主角动作完成。
2. 查看各镜代表帧，以及转场与关键行为前后帧；确认主体、道具、字幕、轮廓与像素尺度。
3. 检查暂停续播、章节跳转后音画位置一致，音频实际长度覆盖整片。
4. 桌面和手机截图检查画面与控件溢出，注意手机上字幕可读性。
5. `ffprobe` 核验最终成片时长、尺寸、帧率、帧数、视频与音频流。两分钟 30 fps 参考片应为 120 秒、3600 帧。
6. 抽取已编码 MP4 中的代表帧，试听对白和音乐，确认最终产物与预览相符。

版本修改前记录可恢复的基线。撤回要恢复对应的故事、场景、声音、字幕、预览控件及生成产物，不凭记忆重画旧版；无法精确恢复时说明缺失的依据。
